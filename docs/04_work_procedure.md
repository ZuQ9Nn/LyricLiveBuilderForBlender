# 04. LyricLiveBuilderForBlender 作業手順書

| 項目 | 内容 |
|---|---|
| 版 | 0.2（ドラフト） |
| 対象 | [02_specification.md](02_specification.md)（仕様書）と [03_detailed_design.md](03_detailed_design.md)（詳細設計書）の実装作業 |
| 読者 | 本アドオンの開発者・コントリビューター、各段階の動作を確認する確認者 |

この文書は、開発を段階（Phase）に分け、段階ごとに次のことをまとめたものです。

1. **開発の作業**：何を作るか（作業項目と完了の条件）
2. **開発側の確認**：自動テスト・スクリプトで開発者が確かめること
3. **確認者の確認**：確認者が Blender（段階によっては Unity・VR 機器）を操作して確かめる手順と、期待する結果

**確認者の確認が終わるまで、次の段階には進みません。** 確認で見つかった問題は、その段階の中で直してから、もう一度確認します。

## 1. 開発環境

| 種類 | 内容 |
|---|---|
| OS | Windows 10/11（Blender と Unity を動かす）。WSL2 からの操作も可 |
| Blender | 5.1 以降で開発・確認する（Blender の公式 MCP サーバーを使うため）。最低対応の 5.0 でも、各段階の終わりに起動確認する |
| Blender MCP | Blender の公式 MCP サーバー（Blender 5.1 以降）。開発者が、確認者と同じ Blender のセッションの状態を調べ、画面のスクリーンショットで確かめるために使う（§2.2） |
| Unity | Unity Hub と Unity 2022.3.22f1 |
| Unity のテスト用プロジェクト | VRChat Creator Companion で作ったワールドのプロジェクト（Worlds SDK・UdonSharp 入り）。**参考用の購入アセットが入ったプロジェクトとは別にする** |
| Unity MCP | 段階 0・4・5 で使う。テスト用プロジェクトにつなぎ替えて使う |
| Python（Blender の外） | `core/` の単体テスト用。Blender 同梱の Python（`<Blender>/5.x/python/bin/python.exe`。numpy 入り）を使う（`tests/run_core.sh`。別の Python は環境変数 `LLB_PY` で指定）。Blender 5.0 の同梱は Python 3.11・numpy 1.26、5.2 は Python 3.13・numpy 2.3 なので、両方で単体テストを行う |
| Blender 5.0（最低対応の確認用） | blender.org の zip 版を展開し、`portable` フォルダを作って使う（設定がそのフォルダに閉じ、普段の Blender に影響しない）。各段階の終わりに、拡張機能の検証・単体テスト・統合テスト・拡張機能としての導入を行う |
| 実機 | PC VR（任意）、Meta Quest（段階 5 の確認に必要） |
| テスト用素材 | フォントは、リポジトリに置けるライセンス（OFL 等）のものを `tests/assets/fonts/` に置く。曲は自作、または権利上問題の無い短い音源を使う |

### 1.1 確認用ファイル

- 開発中の確認は、専用の `.blend`（`tests/manual/check_phaseN.blend`）で行います。普段の制作ファイルでは確認しません。
- 段階ごとの確認用の歌詞は `tests/manual/lyrics_sample.txt` に置きます。中身は、JIZURA のサンプル歌詞（MIT）を元にした、セクション見出し付きの短い歌詞です。

## 2. 作業の決まり

### 2.1 全般

| 項目 | 決まり |
|---|---|
| git | コミットと push は、リポジトリの管理者が手作業で行う。開発者は、変更したファイルの一覧と内容を報告する（自動で行う場合は、別途指示を受ける） |
| 調べてから作る | 実装が難しいと判断した項目は、技術ブログ・GitHub・公式文書を調べてから実装する |
| 改善メモ | 調べている途中で、既に書いたコードの改善点を見つけたら、`internal-docs/improvement_notes.md` にメモする。その段階の作業が終わってから、改善・リファクタリングを行う |
| 文書の更新 | 仕様・設計を変えたら、同じ作業の中で `docs/` の該当箇所を更新する。試作の結果は `docs/05_prototype_results.md` に記録する |
| 権利 | `reference/` の素材（動画・購入アセット・楽曲・テクスチャ・メッシュ・シェーダー）をコピーしない。参考にするのは考え方・手法だけ。JIZURA から移植したコードには、ファイルの先頭に出典（JIZURA, MIT）を書く |
| コード | コメントは英語。1 ファイル 300〜600 行を目安にする。モジュールの依存のルール（設計書 §3）を守る |
| UI の文言 | msgid は英語で書き、同時に `i18n/ja_JP.py` に日本語訳を追加する |
| 判断に迷ったら | 仕様の解釈や、大きな設計の変更が必要なときは、作業を止めて相談する |

### 2.2 MCP の使い方

| 項目 | 決まり |
|---|---|
| 目的 | 確認者に渡す前に、同じ Blender のセッションで開発者が先に確かめる。確認者から報告された問題を、その場の状態を見て再現・調査する |
| 対象のファイル | MCP で操作するのは、確認用の `.blend` だけ。確認者の制作ファイルを開いている間は操作しない |
| 操作の範囲 | 調べる（状態の取得・スクリーンショット）は自由に行う。変更する操作（オブジェクトの生成・削除・設定変更）は、確認用ファイルの `LyricLive` コレクションの中と、アドオンのプロパティに限る |
| 自動テストとの関係 | 自動テストは、MCP を使わずバックグラウンドの Blender（`blender --background`）で実行する。MCP は、画面の見た目と UI の確認のために使う |
| Unity MCP | 参考用の購入アセットのプロジェクトではなく、テスト用プロジェクトにつないで使う |

## 3. 段階ごとの作業と確認

### 段階 0：試作（リスクの確認）

**目的**：本実装の前に、不確かな技術項目を小さなスクリプトで確かめ、設計を確定させる。結果は `docs/05_prototype_results.md` に記録する。

**開発の作業と完了の条件**

| ID | 確かめること | 完了の条件 |
|---|---|---|
| S0-01 | Blender のテキストの大きさと、フォントの em・送り幅（hmtx）の対応。TTC の扱い | 3 書体（ゴシック・明朝・欧文）で、送り幅に沿って並べた文字の間隔がずれない。係数を記録 |
| S0-02 | レイヤードアクションへの大量書き込みの速さ | 6 万キーの書き込みが 5 秒以内。使う API の書き方を記録 |
| S0-03 | 独自メッシュ形式 → Unity Mesh と座標変換 | 「F」の字の立体と回転のトラックが、Blender と Unity で同じ向き・同じ動きに見える |
| S0-04 | Unity のバッチモード起動、ロック判定、エディタを開いたままの自動組み立て | 閉じた状態・開いた状態の両方で、テスト用の manifest から Prefab ができる |
| S0-05 | Timeline の Animation Track で、クリップに無いプロパティが既定値に戻る挙動 | 自己完結のクリップ（設計書 §10.5）で、セクションの境目に見た目の飛びが無い |
| S0-06 | TMP の静的アトラス化と、フォントへの参照の解除 | ワールドのビルドにフォントファイルが含まれない |
| S0-07 | Quest のワールドで、同梱シェーダー（LyricLive/Unlit・Dome）が表示されるか | 表示できない場合は、代替（設計書 §10.3）を既定にする |
| S0-08 | タップの遅延 | 遅延の測定を 3 回行い、ばらつきが ±20 ms 以内 |
| S0-09 | 文字のリトポロジーの既定値 | 代表 100 字で、三角形の数・見た目・穴の保持を比べ、既定値を決める |
| S0-10 | アセットライブラリのタグの読み取り方法 | 100 個のアセットの索引作成が 30 秒以内。不要なデータが残らない |
| S0-11 | UdonSharp で、エディタのスクリプトから U# の部品を付ける方法 | 2 クライアントで再生位置がそろう （2 人以上でのテストまで保留。段階 5 の P5-05 と合わせて確認してよい） |

**開発側の確認**：S0-01〜06、09、10 は、バックグラウンドの Blender・Unity のバッチモード・MCP で確かめ、数値とスクリーンショットを `05_prototype_results.md` に記録する。

**確認者の確認**

| # | 操作 | 期待する結果 |
|---|---|---|
| 1 | Blender で `tests/manual/check_phase0.blend` を開き、上からの視点（テンキー `7`）で `S0-01` コレクションを見る | 3 書体とも、白い行（Blender 自身の並び）とオレンジの行（フォント解析だけで並べた文字）が同じ間隔で並んでいる |

**確認後**：結果を受けて、設計書の「要検証」の項目を確定させる（変更点は設計書 §17 に追記）。

### 段階 2：文字

**目的**：2D・3D の文字が、タイミングどおりに空間に出て、動いて消えるところまで作る。

**開発の作業と完了の条件**

| ID | 作業 | 成果物 | 完了の条件 |
|---|---|---|---|
| P2-01 | 字形メッシュ（2D/3D）とキャッシュ | `text/glyphs.py` | ひらがな・カタカナ・漢字・英数字・記号で、2D・3D の文字ができる |
| P2-02 | 部品のレジストリとモデル | `core/registry.py`、`core/model.py` | 部品の登録と ON/OFF の判定ができる |
| P2-03 | 基本レイアウト（2D/3D 共通の 7 種） | `core/parts/layouts_basic.py` | 1〜20 文字・横書き/縦書きで、視角の基準どおりの大きさに配置される |
| P2-04 | 3D 専用レイアウト（6 種） | `core/parts/layouts_3d.py` | 3D 文字の行で選べ、厚みの側面が見える |
| P2-05 | 動き（登場 10・保持 6・退場 7） | `core/parts/motions_*.py` | 部品の契約のテスト（p=1・p=0 で恒等）が通る |
| P2-06 | プランナー（行の構成）とベイク | `core/planner.py`、`core/bake.py` | 同じシードで同じ結果。間引き後の誤差が許容範囲内 |
| P2-07 | プレビュー（文字） | `preview/scene.py`、`objects.py`、`animation.py`、`materials.py` | 観客カメラで、歌に合わせて文字が出て消える |
| P2-08 | 行の詳細設定（文字に関する項目だけ先に作る） | `ui/lists.py` | 3D 文字・厚み・レイアウト・動き・距離の層・消え方を行ごとに指定できる |

**開発側の確認**：単体テストと、統合テスト（§4.2）の文字の部分が通る。MCP で観客カメラのスクリーンショットを撮り、文字の重なり・はみ出しが無いことを確かめる。

実際に行ったこと：`tests/blender/test_phase2.py`（Blender で再生した位置と core の計算の一致、表示の時間帯、決定性、3D 文字の厚み、4 分の曲の生成時間、訳の漏れと衝突）、core の単体テスト（部品の契約、レイアウトの大きさ・向き、重なり・目からの距離、間引きの誤差）。MCP の代わりに、別に起動した Blender で観客カメラと俯瞰の画面を撮って確かめた（MCP 経由の拡張機能の入れ替えで MCP が止まるため）。

**確認者の確認**

| # | 操作 | 期待する結果 |
|---|---|---|
| 1 | `tests/manual/check_phase2.blend` を開き（`tests/blender/build_check_phase2.py` で作り直せる。段階 1 の確認ファイルでもよい）、「プレビュー」パネルの「生成」を押す | `LyricLive` コレクションの下に、文字・観客カメラができる |
| 2 | 観客カメラから見て（テンキー `0`）再生する | 各行が、タップした時刻に合わせて出て、動いて、消える。文字が重ならず、視界からはみ出さない |
| 3 | ビューを自由に回して、横・後ろから見る | 文字が観客の周り（正面・横・上）に配置されている。近すぎる文字（目から 0.6 m 以内）が無い |
| 4 | 行リストで 1 行選び、「3D 文字」にチェックを入れて、レイアウトを「斜めの壁」にし、もう一度「生成」を押す | その行だけ厚みのある文字になり、斜めに並んで側面が見える。他の行は 2D のまま |
| 5 | 3D 専用レイアウト（斜めの壁・階段・床・立ち並ぶ・迫ってくる・回る立方体）を順に試す | どれも、観客の位置から読める向きで表示される |
| 6 | 行の「消え方」を「セクション末まで残る」にする | その行がセクションの終わりまで空間に残り、セクションの終わりで消える |
| 7 | 同じ設定のまま、もう一度「生成」を押す | 前回とまったく同じ配置・動きになる（決定的） |
| 8 | 4 分程度の曲で「生成」を押した時間を測る | 30 秒以内に終わる（目標） |
