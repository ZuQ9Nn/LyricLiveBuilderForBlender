## 1. 概要

### 1.1 ParticleLive とは

ParticleLive は、VR 空間の中で曲に合わせて歌詞・光の粒・背景・立体物が観客の周りに現れ、変化していく音楽体験です。画面の中を見る映像作品と違い、次の点が特徴です。

- 観客は**空間の中心にいて**、周り（左右・上・足元・背後）を見回せる。
- カメラが無い。「寄る」「パン」などのカメラワークの代わりに、**空間そのもの**（背景・床・粒子・物体）を動かして体感を作る。
- 近く・中くらい・遠くの距離にものを置き分けると、頭を動かしたときのずれ（視差）で立体感と没入感が生まれる。

### 1.2 このアドオンがすること

[JIZURA](https://github.com/852wa/JIZURA)（2D の文字PV自動構成ツール、MIT License）の「歌詞を入れる → 曲を読み込む → タップで同期 → おまかせで作る」という流れを踏襲し、3D・VR 空間向けに作り直します。

```
歌詞を入れる ─▶ フォントを指定 ─▶ 曲を読み込む ─▶ タップで同期 ─▶ おまかせで作る
                                                                  │
                         行ごとの詳細設定で調整（3D文字・レイアウト・粒子・背景・ギミック）
                                                                  │
                                       Blender でプレビュー ─▶ Unity へ出力（Prefab + Timeline）
```

### 1.3 JIZURA との違い

| 項目 | JIZURA | 本アドオン |
|---|---|---|
| 出力 | 2D 動画（16:9 等の画面） | 3D 空間のアセット（Unity Prefab） |
| 見る人 | 画面の前 | 空間の中心 |
| 文字 | 厚みのない 2D | 2D（板）と、厚みのある 3D を行ごとに選べる |
| 演出 | 画面効果・カメラワーク | パーティクル・背景ドーム・ステージギミック |
| 構成の単位 | カット | 行とセクション（Aメロ・Bメロ・サビ…）。行の詳細で、1 行を複数のカットに分けることもできる |
| フォント | Google Fonts を読み込む | **同梱しない**。利用者が端末のフォントファイルを指定する |

### 1.4 対象外

- アバター、およびアバター用ギミック（本アドオンはワールド専用）
- 動画ファイル（MP4 等）の書き出し、After Effects 向けの書き出し
- Unity で加えた変更を Blender に取り込む機能（常に Blender → Unity の一方通行）

## 2. 動作環境

| 区分 | 対象 |
|---|---|
| Blender | **5.0 以降**（Extension 形式） |
| Unity | **2022.3.22f1**（VRChat の対応版）、Built-in Render Pipeline |
| VRChat | Worlds SDK。Udon 同期を使う場合は UdonSharp |
| 出力の対象機器 | PC VR、Android / iOS（VRChat モバイル）、Meta Quest |
| OS | Windows（主）。macOS / Linux は、Unity の起動パスを指定すれば動く範囲で対応 |

- Unity が端末にインストールされていることを前提にします。見つからない場合は、Unity 出力の実行時にエラーダイアログを出します（§9.2）。
- 外部の Python パッケージは原則として使いません。必要な場合は Extension の `wheels` として同梱できるもの（純 Python・許容的ライセンス）に限ります。

## 3. 用語と座標系

| 用語 | 意味 |
|---|---|
| 行 | 歌詞の1行（1フレーズ）。タップ同期の単位 |
| セクション | イントロ・Aメロ・Bメロ・サビ・間奏・アウトロなどの区切り。背景の切り替えと、Unity のアニメーション分割の単位 |
| テーマ | 背景・パーティクル・ギミックの組み合わせ（例：「朝の庭」「夜の街」「星空」） |
| 4分類 | 文字モーション／パーティクル／背景シーン／ステージギミック |
| 観客点 | 観客が立つ中心点（原点）。本アドオンは**中心型**（観客を中心に、演出が 360° を囲む）を採用 |

### 3.1 座標系

- Blender ではメートル単位・Z 上向き、観客点＝原点、正面＝+Y 方向とします。
- Unity への変換は、Blender の (x, y, z) を Unity の (x, z, y) に入れ替えるだけで済みます（右手系 → 左手系の変換が、Y と Z の入れ替えで成り立つため）。
- Unity へは Y 上向き・正面＝+Z に変換して出力します。
- 目線の高さの既定は 1.5 m（設定で変えられる）。

### 3.2 距離の層

観客点からの距離で、演出を置く場所を3層に分けます。半径は設定で変えられます。

| 層 | 既定の半径 | 主に置くもの |
|---|---|---|
| 近景 | 0.8〜2 m | 歌詞（手が届く距離）、小さなきらめき |
| 中景 | 2〜6 m | 歌詞、パーティクルの発生範囲、ステージギミック |
| 遠景 | 6 m〜ドーム | 遠景オブジェクト（月・山並み・街並み）、背景ドーム（既定の半径 60 m） |

## 4. 全体構成

### 4.1 処理の流れ

```
[Blender]
 歌詞・フォント・曲・タイミング・設定（シーンのプロパティ）
   │
   ▼  planner（JIZURA のロジックを移植・拡張）
 プラン（JSON 相当のデータ）：セクション・行・文字・部品の選択・パラメータ・時間
   │
   ├─▶ preview builder：Blender のシーンにオブジェクト・マテリアル・キーフレームを生成（確認用）
   │
   └─▶ unity exporter：
         ・メッシュ（文字・ギミック・ドーム）を独自のバイナリ形式で出力（Unity 座標に変換済み）
         ・パーティクル／背景／トランジション／アニメーションの定義を manifest（JSON）で出力
         ・生成したテクスチャ（PNG）を出力
         ・Unity 側の組み立てスクリプト（C#）を配置
                │
[Unity]         ▼
 組み立てスクリプトが manifest を読み、ParticleSystem・Material・AnimationClip・Timeline・Prefab を生成
```

**パーティクルとアニメーションは Unity 側で組み立てます。** Blender のパーティクルは Unity に持って行けず、FBX のアニメーションではマテリアルの値や表示切り替えを正しく渡せないためです。メッシュも FBX を使わず独自形式で渡し、Unity 側で Mesh アセットを作ります。FBX の軸変換・スケール・インポート設定のずれを避け、文字の位置とアニメーションの整合を確実にするためです。Blender のプレビューは「Unity で組み上がるものの近似」です。

### 4.2 モジュール構成

機能ごとにサブパッケージに分け、1 ファイルが大きくなりすぎないようにします（目安：1 ファイル 300〜600 行）。

```
lyric_live_builder/            # Blender Extension 本体
  blender_manifest.toml
  __init__.py                  # register / unregister
  i18n/                        # 日本語・英語の翻訳辞書
  core/                        # Blender に依存しない純 Python（単体テスト可能）
    lyrics.py                  # 歌詞の記法の解析・チャンク分割
    timing.py                  # タイミング計算・セクション推定
    audio.py                   # BPM・拍・音量・スペクトラム（numpy）
    rng.py                     # 決定的ハッシュ・乱数・イージング
    styles.py / moods.py       # スタイル・雰囲気・テーマのデータ
    planner.py / omakase.py    # 構成の自動生成
    parts/                     # 部品の定義（レイアウト・動き・粒子・背景・ギミック）
  text/                        # フォント読み込み・文字メッシュ（2D/3D）・字形の部品分解
  preview/                     # プランから Blender のシーンを組み立てる
  export_unity/                # メッシュ・manifest・テクスチャの出力、Unity の検出・起動
    unity_templates/           # Unity 側の組み立てスクリプト（C#）とシェーダー
  ui/                          # パネル・オペレーター・UIList
mesh_optimizer/                # モバイル最適化（独立パッケージ。§10）
```

- `core/` は `bpy` を import しません。Blender 無しで planner や音声解析をテストできます。
- `mesh_optimizer/` は本体のどのモジュールも import しません。本体から呼ぶときは公開関数（`optimize_text_mesh()` 等）だけを使います。同じリポジトリから、単体の Extension としてもビルドできるようにします。
- コード中のコメントは英語で書きます。UI の文言は翻訳辞書を通します。

## 5. 入力と同期

### 5.1 歌詞を入れる

- 歌詞は Blender のテキストデータブロックに保存します。入れ方は次の 3 つです。Blender のテキストエディタは日本語入力（IME）に対応していないため、外部のアプリで書けるようにします。
  - **外部エディタで編集**（メモ帳など、OS で `.txt` に関連付けられたアプリ）：ボタンで今の歌詞を開きます。そのアプリで保存すると、自動で取り込みます。
  - **クリップボードから貼り付け**：コピーした歌詞を 1 回のクリックで取り込みます。今の歌詞があるときは、確認してから置き換えます。
  - **ファイルから読み込む**：`.txt`・`.lrc` を選びます。文字コードは UTF-8・UTF-16・Shift_JIS を自動で判別します。
- どの方法でも、タップの時刻など行ごとの設定は、同じ歌詞の行に引き継ぎます。
- パネルの「歌詞を開く」で、Blender のテキストエディタでも見られます（英数字の入力と貼り付けはできます）。
- JIZURA の記法をそのまま使えます。

| 記法 | 意味 |
|---|---|
| `夜明けの色を/覚えてる` | `/` でチャンクの切れ目を指定 |
| `*透明*` | 強調（大きく・インパクトのある演出が選ばれやすい） |
| 行末の `!` | 強いアクセント（フラッシュ・パーティクルのバースト） |
| `歌詞|注釈` | 注釈（小さな添え文字） |
| `[01:23.45]歌詞` | LRC のタイムスタンプ |
| `# …` | コメント |
| `[ti:曲名]` `[ar:歌手]` | メタ情報 |

- **セクションの見出し（追加の記法）**：`[A]` `[B]` `[サビ]` のような、単独の行に書いた見出しを、次の見出しまでのセクションとして扱います。

| 見出しの例 | セクション種別 |
|---|---|
| `[イントロ]` `[Intro]` | intro |
| `[A]` `[Aメロ]` `[Verse]` | verse |
| `[B]` `[Bメロ]` `[Pre-Chorus]` | prechorus |
| `[サビ]` `[Chorus]` | chorus |
| `[間奏]` `[Interlude]` | interlude |
| `[Cメロ]` `[Bridge]` `[大サビ]` | bridge |
| `[アウトロ]` `[Outro]` | outro |

  LRC のタイムスタンプ（`[01:23.45]`）とは形式で区別します。

### 5.2 フォントを指定する

- フォントは同梱しません。利用者が端末の .ttf / .otf / .ttc を指定します。.ttc（複数の書体を含むファイル）は、Blender の制約で先頭の書体だけを使います。
- 書体の役割は JIZURA と同じ4つです。役割ごとにフォントファイルを割り当てます。

| 役割 | 主な用途 |
|---|---|
| 見出し（display） | 強調・サビの大きな文字 |
| 明朝（serif） | 静かな行・縦書き |
| 本文（body） | 通常の行・注釈 |
| 等幅（mono） | 数字・カウンターなどの装飾 |

- 指定が無い役割は「本文」のフォントで代用します。1つも指定が無い場合は、おまかせと出力を実行できません（案内を表示します）。
- 歌詞の文字がフォントに含まれていない場合（字形が無い場合）は、その文字の一覧を警告として表示します。
- 字幅の計測は、フォントファイルの hmtx / vmtx テーブルを読む簡易パーサーで行います（Blender のテキストオブジェクトからは字幅を取れないため）。
- **利用者への注意**：出力物には、フォントの字形がメッシュとして含まれます。フォントによってはライセンスで「アウトライン化・埋め込み・再配布」を制限しているので、利用者が自分で確認する必要があります。README とパネルの「利用について」に、この注意を表示します。

### 5.3 曲を読み込む

- 対応形式：Blender（Audaspace）が読める形式（WAV / MP3 / OGG / FLAC / M4A など）。
- 読み込むと、次のことを行います。
  - VSE（ビデオシーケンサー）にサウンドストリップを置き、シーンの長さを曲に合わせる。
  - 音声を解析する。JIZURA の方式（オンセット強度 → 自己相関 → 位相探索）を numpy で移植し、次の3つを求める。
    - BPM・拍
    - 正規化した音量包絡（50 Hz）
    - 帯域別の簡易スペクトラム（ギミックのバー用）
- BPM と最初の拍は手動でも直せます。

### 5.4 タップで同期

- タップの速さを 1×・0.75×・0.5× から選べます（音程は保ちます）。タップの途中でも変えられ、今の位置からすぐ切り替わります。遅くしても、記録するのは本来の速さの時刻で、遅延の補正も曲の時間に換算します。
- タップの間、「タップ同期」のボタンは「終了」に変わります。Esc でも終了できます。
- 開始前のカウントダウン（3、2、1）を選べます。
- 行の詳細の「この行からタップ」で、途中の行からやり直せます。その行の少し前から再生し、前の行の時刻は残します。
- 間違えたら Backspace で取り消します。曲は約 3 秒戻るので、すぐ押し直せます。
- 「タップで同期」を押すと曲が先頭から流れます。各行の歌い始めでキー（既定：`T`。Blender では Space が再生に割り当て済みのため）を押すと、その時刻を行の開始として記録します。
- キーを押してから記録されるまでには、Blender のイベント処理と音声出力の遅れが乗ります。拍に合わせてタップする「遅延の測定」を用意し、測った遅れ（ミリ秒）を記録時刻から差し引きます。
- 記録はタイムラインマーカーとしても残ります。マーカーを動かして微調整し、「マーカーから行の開始時刻を取り込む」でも反映できます。
- `Esc` で中断、`Backspace` で直前の記録を取り消せます。
- **文字単位のタイミング（オプション）**：行の開始と終了から、文字数（かなは短く、漢字は長め）で自動で配分します。文字ごとに歌に合わせて現れる演出（§7.4）に使います。行の詳細から、文字単位でタップし直すこともできます。
- LRC のタイムスタンプ、または手動入力の秒数がある行は、それを優先します。

### 5.5 セクション

- 歌詞に見出し（§5.1）があれば、それを使います。
- 見出しが無い場合は、次の手がかりから自動で推定します。推定結果は行リストで変更できます。
  - 空行
  - 行の間の長い空き（間奏）
  - 曲の音量の大きな変化（サビの立ち上がり）
  - 同じ歌詞の繰り返し（サビの反復）
- セクションごとに**テーマ**を割り当てます。既定の対応：イントロ＝夜明け、Aメロ＝朝、Bメロ＝昼、サビ＝夜、間奏＝星空。おまかせで変わり、手動でも変えられます。

## 6. 構成の自動生成（おまかせ）

### 6.1 おまかせで作る

押すたびに、次のものをまとめてランダムに決め直します（決定的シードによる）。

| 項目 | 内容 |
|---|---|
| 雰囲気 | グリッチ / しっとり / ポップ / グラフィック / エディトリアル / エモーショナル / ホラー / 全部入り（JIZURA と同じ） |
| スタイル | 配色セット・書体の役割の使い分け（JIZURA の 27 種。ホラーの 3 種は雰囲気がホラーのときだけ選ぶ） |
| 演出の強さ | 動きの強さ・パーティクルの量・装飾の量・世界の切り替えの頻度 |
| テーマの割り当て | セクションごとの背景・パーティクルのセット・ギミック |
| 文字の構成 | 行ごとのレイアウト・登場・保持・退場・距離の層 |
| 配色 | アクセント色（ときどきランダム配色。背景とのコントラストを自動で補正） |
| シード | 新しいシード |

- 変わらないもの：歌詞・フォント・曲・タイミング・セクション・鍵をかけた行。
- **前の案 / 次の案**：おまかせで出した案を行き来できます。
- **ここだけ変える**：スタイル／配色／雰囲気／文字の構成／パーティクル／背景／ギミックのどれか1つだけを振り直します。
- **使う演出の範囲**：JIZURA の「追加分の演出も使う」「和風の演出も使う」と同じ考え方で、部品ごとの ON/OFF と、まとめての切り替えを持ちます（「追加分」「和風」のまとめての切り替えは、部品を増やす段階 6 で加えます）。

### 6.2 行ごとの詳細設定

行リスト（UIList）で行を選ぶと、詳細を設定できます。指定した項目はおまかせ・再抽選で変わりません（鍵）。

| 項目 | 内容 | 既定 |
|---|---|---|
| 開始・終了時刻 | 秒で直接入力 | タップ同期の値 |
| セクション | 所属セクションの変更 | 自動 |
| **3D 文字（厚みあり）** | チェックを入れた行だけ、厚みのある 3D 文字で出力する | **OFF** |
| 厚み・ベベル | 3D 文字の厚み（文字の大きさに対する割合）とベベル | 15% / 小 |
| レイアウト | §7.3 のパターンから選ぶ。3D 文字の行では 3D 専用のパターンも選べる | おまかせ |
| 登場・保持・退場 | §7.4 の部品から選ぶ | おまかせ |
| 距離の層 | 近景 / 中景 / 遠景 | おまかせ |
| カット | 1 行を何回に分けて見せるか（おまかせ / 1〜6）。文節で区切り、歌う時刻に合わせて順に出す。カットごとに、レイアウト・動き・距離を抽選する（行で指定した項目は全カットに同じものを使う）。2 つ以上に分けた行は、セクションの終わりまで残らない | おまかせ（分けない） |
| 消え方 | 次の行で消える / セクションの終わりまで残る（蓄積） | おまかせ |
| 視線の誘導 | この行の前に、視線を誘導する演出を出すか（§7.6） | 自動 |
| パーティクル | この行の間だけ追加するパーティクルのプリセット。「歌詞から選ぶ」では、行の言葉からプリセットを選ぶ（例：星 → きらめく星、花火 → 花火、桜 → 花びら）。合う言葉が無ければ「おまかせ」と同じ | セクションのテーマに従う |
| 背景 | この行から背景を変える（トランジションも指定） | セクションのテーマに従う |
| ステージギミック | この行で発動するギミック | なし / おまかせ |
| 再抽選・鍵 | この行だけ振り直す・固定する | — |

### 6.3 試し見（Before / After）

行やセクションの項目の名前だけでは、変えるとどうなるかが分かりにくいので、変える前と後を並べて見られるようにします。

- 「セクションと行」パネルの「試し見」で、今の 3D ビューの左側に 2 つの領域を足します。左が **Before**（最後に「生成」したときの設定）、その右が **After**（今の設定）で、観客の位置から同じ向き・同じ時刻で見せます。片方の視点を動かすと、もう片方も同じように動きます。LyricLive のサイドバーはそのまま右に残るので、項目を変えながら見比べられます。
- 選んだ行の時間（少し前から）を、曲と一緒に繰り返し再生します。セクションを選んだときは、そのセクションの始まり（背景の切り替えとトランジション）を再生します。
- 行やセクションの項目（テーマ、背景、トランジション、3D 文字、レイアウト、登場・保持・退場、距離の層、カット、消え方、視線の誘導、ステージの物体、出し方、この行のパーティクル、この行からの背景、選び直す・鍵）を変えると、After がすぐに作り直されます。
- 項目の変更は、行やセクションの設定にすぐ入ります。ただし、**メインのプレビューは「確定」か「生成」を押すまで変わりません**。このことを、After の画面と「セクションと行」パネルに表示します。
- 「確定」でメインのプレビューを作り直し、Before もその内容になります。「元に戻す」で、選んだ行（セクション）の項目を Before の設定に戻します。
- **消音**（チェック、既定は OFF）：ON の間は曲の音を消します。試し見を閉じると、元の音の設定に戻ります。
- 「閉じる」で 2 つの領域を消し、元の配置に戻します。
- 「確定」「元に戻す」「消音」「閉じる」は、After の上部と「セクションと行」パネルの両方にあります。
- 試し見の間は、繰り返しのために、タイムラインのプレビュー範囲をその行の時間にします。閉じると元に戻します。タップ同期・遅延の測定を始めたときは、試し見を自動で閉じます。
- 試し見で見えるのは、選んだ行（セクション）に関係するものだけです（他の行の文字は出さない）。視線の誘導は、前の行を見ていた前提ではなく、正面を見ていた前提で作ります。
- おまかせ・演出のスライダーなど、全体の設定を変えたときは「試し見を更新」で After を作り直します。

## 7. 文字モーション

### 7.1 2D 文字と 3D 文字

| 種類 | 作り方 | 用途 |
|---|---|---|
| 2D 文字（既定） | フォントの輪郭をメッシュ化した、厚みのない板（両面表示） | 通常の行。軽い |
| 3D 文字 | 同じ輪郭を押し出し、ベベルを付けた立体 | 行の詳細で「3D 文字」にチェックを入れた行だけ |

- どちらも**1文字＝1オブジェクト**で作ります（文字ごとに動かすため）。行は親の Empty にまとめます。
- 同じ文字・同じフォント・同じ種類のメッシュは共有します（データ量を減らすため）。
- 字形の部品分解（分解→集合などの動きに使う）は、メッシュを「ばらばらのパーツ」に分けて行います。

### 7.2 文字の材質

- 文字のマテリアルは「Unlit（発光色）」「Lit（陰影あり）」「MatCap」の3種類から選びます。色はスタイルの配色に従います。
- 3D 文字では、側面の色（表面より暗い色・アクセント色）を選べます。
- 発光（Emission）の強さは時間で変えられます（拍で光る、など）。

### 7.3 レイアウト（空間配置）

観客点から見た配置のパターンです。2D・3D の両方で使えるものと、3D 文字専用のものがあります。

| パターン | 2D | 3D | 内容 |
|---|:-:|:-:|---|
| 正面 | ○ | ○ | 観客に正対する平面。距離の層を選べる |
| 見上げ | ○ | ○ | 目線より上に置き、観客に向けて後ろに傾ける |
| 囲む円弧 | ○ | ○ | 観客を中心とした円弧に沿って、横に回り込む |
| 螺旋 | ○ | ○ | 観客の周りを昇る／降りる |
| 互い違い | ○ | ○ | 文字を上下・傾きを交互にずらす |
| 縦書きの柱 | ○ | ○ | 縦書きの行を柱のように立てる |
| 散らし | ○ | ○ | 中景の空間に文字を散らす（奥行きもばらつかせる） |
| **斜めの壁** | — | ○ | 行を斜め（既定 35°）に回し、厚みの側面が見える壁のように並べる。左右どちらに傾けるかを選べる |
| **奥行きの階段** | — | ○ | 文字ごとに少しずつ奥へずらし、横から見ると階段になる |
| **床に寝かせる** | — | ○ | 足元の床に文字を寝かせて並べる。見下ろすと読める |
| **立ち並ぶ** | — | ○ | 文字を床に立てて、観客の周りに並べる（積み木・ドミノ風。倒れる退場と組み合わせる） |
| **迫ってくる** | — | ○ | 遠景の巨大な文字が近づき、観客の横を通り抜ける |
| **回る立方体** | — | ○ | 立方体の面に文字を貼り、回転させて次の面を見せる |

- 各パターンは、行の長さ・縦書き/横書き・距離の層に応じて大きさを自動で調整します。
- 文字の大きさは、距離に比例した見かけの大きさ（視角）を基準に決めます。どの距離でも読める大きさにするためです。

### 7.4 動き（登場・保持・退場）

JIZURA の動きの部品を、3D 空間向けに作り直します（Z 方向の移動と 3 軸の回転を加える）。初版では基本セットを実装し、残りは段階的に追加します。

### 7.5 VR での見やすさ・酔い対策

- 観客の真正面・目線の高さを、主な歌詞の位置にします。
- 全体の回転（特に視線の軸まわりのロール回転）や急な加速は使いません。空間全体が動く演出（トンネル等）は、速さの上限と、中央に動かない目印を置くことを既定にします。
- 強い点滅（白飛び）は 1 秒あたり 3 回以下にします。

### 7.6 視線の誘導

VR では、観客の視野の外に出た文字に気づきにくくなります。そこで、文字が視野の外に出るときは、その少し前に、視線を自然に誘導する演出を出します。矢印や記号のような、あからさまな表現は使いません。

- **判定**：観客が今見ている方向を、直前の行の位置から推定します。新しい行がそこから 30° 以上離れていれば、その行に誘導を付けます。正面に続けて出る行には付けません。
- **表現**（360° 映像の研究で、止まった光より、動く光のほうが視線を動かすと報告されているため、動く光を主役にします）

| 演出 | 内容 | 使う場面 |
|---|---|---|
| 光の筋（主役） | 文字と同じ色の小さな光の粒が数個、短い尾を引いて、推定した視線の位置から行の位置へ、ゆるい弧を描いて流れる（約 0.7 秒。遠いほど長くかけ、180° で 1.2 秒）。着いた瞬間に文字が出る。行の設定が「あり」で、推定した視線が行に近いときは、行から 45° 離れた脇から流す | 誘導を付けるすべての行 |
| 予兆の灯り | 行の位置に、ぼんやりした光が 0.4 秒かけて現れ、文字の登場とともに消える | 視野の端に入る位置 |
| ドームに差す光 | 背景ドームの、その方向だけがゆっくり明るくなる（点滅ではない） | 真横や後ろなど、視野の外 |

- **全体の演出と混ざらないための決まり**
  - 時間：誘導は「文字が出る約 0.7〜1.2 秒前から、出る瞬間まで」に限ります（Udon で視線に合わせる版は最長 1.5 秒前から）。行に結び付いたパーティクル（`!` のバーストなど）は、文字が出てから始めます。
  - 動き：誘導だけが「1 点へ集まる」動きをします（テーマのパーティクルは、漂う・広がる動き）。
  - 色：誘導は文字の色（本文の白・強調の色）を使います（テーマのパーティクルは配色の色）。
  - 層：誘導は、テーマのパーティクルとは別の層です。文字の構成と一緒に決まるので、おまかせや「ここだけ変える」でパーティクルを振り直しても、消えたり、タイミングがずれたりしません。
- **設定**：「演出」パネルで入/切と強さ、行の詳細で「自動 / あり / なし」を選べます。
- 「ライト」は、Unity の実際のライトではなく、加算合成の光とドームの明るさで表します（Quest ではリアルタイムのライトが重く、文字は陰影の無いマテリアルのため）。
- ドームに差す光は、ゆっくりした明暗にし、§7.5 の点滅の回数の制限にも数えます。
- 音による誘導は行いません（曲に効果音が混ざるため）。
- **Udon で視線に合わせる版**（Udon 同期を付けた場合）：各観客のヘッドセットの向きを読み、すでに行の方を見ている人には誘導を出さず、光の筋をその人の実際の視線の位置から出します（光はいったん視線の位置に現れてから流れる）。見た目だけの処理なので、同期の通信は使いません。Udon を使わない場合は、推定した視線で動きます。

### 8.1 パーティクル

ステージ全体に出すパーティクルです。プリセット（設定の組）として持ち、テーマ・セクション・行に割り当てます。

**形状**

| 種類 | 形状 |
|---|---|
| 2D（テクスチャ付きビルボード） | 丸、ぼかし丸（光の粒）、三角、四角、×、六角形、八角形、泡、星、きらめき（十字光）、花びら、ハート、音符、雪の結晶、リング |
| 3D（メッシュ） | 立方体、六角柱、八面体、正二十面体、板の破片、三角錐 |

- 2D のテクスチャは、アドオンが**プロシージャルに生成**します（PNG、1枚のアトラス）。外部の画像素材は使いません。利用者が自分の画像を追加することもできます。

**プリセットの設定項目**（Unity の ParticleSystem に対応）

| 項目 | 内容 |
|---|---|
| 発生範囲 | 観客を囲む円錐（床から湧く）・半球（空から降る）・円/リング（周りを囲む）・箱・球・文字のメッシュ。半径は距離の層で指定する |
| 量・寿命・速度・大きさ・重力 | 範囲（最小〜最大）で指定 |
| 色 | スタイルの配色から選ぶ。寿命中の色・透明度の変化 |
| 動き | ノイズ（漂う）、回転、大きさの変化、軌跡（トレイル） |
| 破裂 | バースト、サブエミッター（花火のように二段で弾ける） |
| 合成 | 加算 / 半透明 |
| 時間変化 | セクションや行に合わせて、量・速さを変える（盛り上がりで増やす） |

**初版のプリセット例**：光の粒、星空、流れ星、雪、花びら、泡（水中）、花火、ハート、音符、浮遊する立方体、回る破片の輪（観客の上下を回るリング）、ワープ（放射する光の筋）。

**Blender でのプレビュー**：粒ごとの位置を時刻の式で計算し、フレームごとに表示します（見た目の確認用。Unity は ParticleSystem が自分で計算するので、完全には一致しません）。

### 8.2 背景シーン

- 観客を包む**内向きのドーム**（球に近い多面体。法線を内側に向けたアイコスフィア、既定の半径 60 m）の内側に、マテリアルを貼って背景を作ります。Unity の Skybox に相当します。
- 背景の種類

| 種類 | 内容 |
|---|---|
| 単色 | 1 色 |
| 上下グラデーション | 天頂・地平・足元の 3 色（朝・昼・夕・夜のプリセット） |
| 帯グラデーション | 段階的な濃淡の帯（空間の大きさを感じさせる） |
| 模様 | JIZURA の背景模様の一部（同心円・格子・水玉など）をドームに展開したもの |
| 画像 | 利用者が指定した 360° パノラマ画像（正距円筒） |

- **遠景オブジェクト**：月・太陽・山並み・街並みのシルエット・水平線（水面）などを、ドームの内側の遠景に置けます。
- **時間帯プリセット**：朝・昼・夕・夜・夜明け・星空。セクションのテーマから選ばれます（例：Aメロ＝朝 → Bメロ＝昼 → サビ＝夜）。
- **背景の変更とトランジション**：曲の途中で、色の変更やマテリアルの差し替えができます。切り替えのトランジションは次から選べます。

| トランジション | 内容 |
|---|---|
| クロスフェード | 前の背景から次の背景へ徐々に変わる |
| ホワイトアウト / 暗転 | 一度白（黒）に飛ばしてから次の背景へ |
| 上から / 下から / 横からワイプ | 境界線が移動して切り替わる（境界のぼかし幅を指定） |
| 広がるリング | 観客の正面（または真上）から円が広がって切り替わる |
| ディゾルブ | ノイズ模様で、まだらに切り替わる |

- 実装：ドームは 1 枚だけにし、シェーダーが「前の背景（A）」と「次の背景（B）」の2組の設定を持って、「切り替え進行度」の値で混ぜます。ドームを2枚重ねる方式は、画面全体を半透明で二重に描くことになり、Quest で重いため使いません。ワイプ・リング・ディゾルブは本アドオンに同梱する小さなシェーダー（Unity 用・MIT）で行います。モバイル向けの簡易版もあります。
- VRChat の公式文書は、Quest のワールドでのカスタムシェーダーの可否を明記していません（Quest のアバターは SDK のシェーダーのみ）。そのため、同梱シェーダーが使えない場合に備えて、VRChat SDK の Mobile シェーダーだけで成り立つ代替（ドームは単色・グラデのテクスチャ差し替えとクロスフェード相当の色変化のみ）も出力できるようにします。

### 8.3 ステージギミック

**枠組み**：ギミック＝「物体」×「出し方」×「タイミング（行・セクション）」。

| 出し方 | 内容 |
|---|---|
| 床から生える | 床の下からせり上がる（スケール・位置） |
| 空から降る | 上から落ちて着地する（弾む） |
| 壁から出る | 観客を囲む見えない壁（中景の円）から押し出される |
| ポップ | その場でスケール 0 から出る |
| ひっくり返って現れる | 床の一部（ステージ）が回転し、裏側に乗っている物体が現れる |
| 開く | 箱の壁が開いて中が現れる（回転） |
| 溶けて消える | ディゾルブ（同梱シェーダー）で消える |

- 「ステージがひっくり返る」など大きな変形は、部品ごとの移動・回転で作ります（ボーンは使いません）。
- **音のスペクトラムバー**：曲から自動生成し、観客を囲む円形に並べます（物体の入手は不要）。「演出」パネルで、なし・サビだけ・曲全体を選べます。

#### 8.3.1 歌詞にちなんだ物体の入手

歌詞の単語に合う物体を、次の順に探します。

```
① ユーザー登録ライブラリにタグが一致する物体がある → それを使う（最優先）
② 内蔵の基本形に一致するものがある             → それを使う
③ どちらにも無い                                → キーワードを 3D 文字の紋章として出す
```

| 入手元 | 内容 |
|---|---|
| ① ユーザー登録ライブラリ | Blender 標準の**アセットブラウザ**を使う。利用者が自分の .blend / FBX の物体をアセットとして登録し、キーワードを**タグ**として付ける。アドオンは、設定で指定したアセットライブラリ（またはカタログ）からタグで検索する |
| ② 内蔵の基本形 | プリミティブの組み合わせでアドオンが生成する 25 種（星・月・太陽・雲・ハート・花・雪の結晶・雨粒・羽・扉・鍵・時計・傘・音符・王冠・宝石・ろうそく・木・柱・アーチ・箱・指輪・鐘・葉・家）。外部の素材は使わない |
| ③ キーワードの紋章 | 歌詞の単語を、3D 文字（厚み・ベベル付き）の紋章として出す。文字メッシュの仕組み（§7.1）を流用する。どんな単語にも対応できる |

- **単語とタグの照合**：アドオンに同義語の辞書を内蔵します（例：「星・スター・star・☆」→ `star`）。歌詞の行・チャンクにキーワードが含まれていれば一致とします。利用者のタグもこの辞書を通すので、日本語・英語のどちらでタグを付けても一致します。辞書は、内蔵の基本形の種類分から始めて増やします。利用者が単語を追加することもできます。
- **登録物体の取り込み時の正規化**：大きさ（既定の高さ）・原点（底面の中心）をそろえます。正面は Blender の標準の -Y とみなします。色は、ベースカラーとそのテクスチャを頂点の色に写します。モバイル最適化（§10）が ON のときは、減面も行います。
- **権利**：登録した物体の権利確認は利用者が行います。本アドオンは素材を同梱・配布しません。素材の入手先として、ライセンスが明確な CC0 素材サイトなどを README で案内します（自動ダウンロードはしません）。
- **外部生成（AI による Text-to-3D 等）は本体に組み込みません。** 理由は次のとおりです。
  - API キー・料金・ネットワークが必要
  - 出力物の権利条件がサービスごとに違う
  - 品質とポリゴン数が安定しない
  - 同じシードでも同じ結果にならない（おまかせの再現性が崩れる）

  外部生成を使いたい場合は、生成したモデルを①に登録すれば同じように使えます。要望が強ければ、将来、本体と切り離した拡張として追加を検討します。

## 9. Unity への出力

### 9.1 出力の設定

| 項目 | 内容 | 既定 |
|---|---|---|
| Unity プロジェクト | 出力先の VRChat ワールドプロジェクトのフォルダ | （必須） |
| Unity エディタ | Unity.exe の場所。Unity Hub の標準のインストール先から 2022.3.22f1 を自動で探し、手動でも指定できる | 自動 |
| 出力フォルダ名 | `Assets/LyricLive/<曲名>/` | 曲名 |
| **TextMesh Pro に変換** | 2D 文字の行を TextMesh Pro に変換する。3D 文字を指定した行は、メッシュのまま出力する | **OFF** |
| **モバイル最適化** | §10 の最適化を行う | **OFF** |
| **Udon 同期スクリプト** | 後から入室した人にも再生位置を合わせる UdonSharp スクリプトと、開始/停止ボタンを付ける。視線の誘導を、各観客の視線に合わせる（§7.6） | **OFF** |
| マテリアル | VRChat 用（VRChat SDK の Mobile シェーダー）／Unity 標準 | VRChat 用 |

### 9.2 出力の手順

1. **Unity の確認**：Unity エディタが見つからない場合はエラーダイアログを出して中止します。2022.3.22f1 が無く、他の 2022.3 系がある場合は、ダイアログに見つかった版を示します。「Unity エディタ」にその場所を指定すれば、その版で続行できます。Timeline パッケージが無いプロジェクトも、追加の方法を示して中止します。
2. **素材の書き出し**：プロジェクトの出力フォルダに、メッシュ（独自形式）・テクスチャ（PNG）・manifest（JSON）・組み立てスクリプト（C#、`Editor` フォルダ）・同梱シェーダーを書き出します。
3. **組み立て**
   - そのプロジェクトを Unity エディタで開いていない場合は、Unity をバッチモードで起動して組み立てます（`-batchmode -executeMethod`）。終わったらログを読み、結果を表示します。
   - 開いている場合（プロジェクトのロックファイルで判定）は、素材を置くだけにします。Unity に切り替えたときに、組み立てスクリプトが自動で manifest を読んで組み立てます。メニュー（`Tools > LyricLive > Rebuild All Songs`）から手動でもやり直せます。
4. 同じ曲をもう一度出力すると、出力フォルダの中身を作り直します。**Unity 側で加えた変更は上書きされる**ため、カスタマイズする場合は、生成物を別の場所にコピーしてから編集するよう案内します。

### 9.3 生成される Prefab

シーンに置くだけで再生できる、1 つの Prefab にまとめます。

```
LyricLive_<曲名>  (PlayableDirector, AudioSource)
├─ Text          (Animator)  … 行ごとの親 → 文字ごとのオブジェクト
├─ Particles     (Animator)  … プリセットごとの ParticleSystem
├─ Background    (Animator)  … ドーム・遠景オブジェクト
├─ Gimmicks      (Animator)  … ギミックの物体
└─ Sync          (UdonSharp, オプション)
```

- 原点＝観客点。ワールドの観客を立たせたい位置に置きます。

### 9.4 アニメーションの分割と Timeline

- 1 本の巨大なアニメーションにはしません。**セクション × 4分類**で AnimationClip を分けます。

  例：`Chorus1_Text.anim`、`Chorus1_Particles.anim`、`Chorus1_Background.anim`、`Chorus1_Gimmicks.anim`
- 1 つの Timeline（`<曲名>.playable`）で全体を制御します。

| トラック | 中身 |
|---|---|
| Audio | 曲 |
| Text | セクションごとの文字のクリップを順に並べる |
| Particles | 同上（発生量の変化）。発生の ON/OFF は Control Track / Activation Track |
| Background | 同上（色・切り替えの進行度） |
| Gimmicks | 同上 |
| Markers | セクション名・行のマーカー（編集の目印） |

- クリップの名前・トラックの名前は、Unity 上で探しやすい規則にします（`<セクション番号>_<セクション名>_<分類>`）。
- ループする小物（回転し続けるギミック等）は、本編とは別の短いループクリップにします。

### 9.5 TextMesh Pro 変換（オプション）

- 指定したフォントから、TextMesh Pro のフォントアセットを Unity 側で作ります。**歌詞に使う文字だけを含む静的なアトラス**にし、作成後はフォントファイル本体への参照を外します。ワールドのビルドにフォントファイル自体が含まれるのを避けるためです（含めるとフォントの再配布になりうるため）。
- 文字ごとに動かすため、1 文字＝1 つの TextMeshPro オブジェクトにします。
- 3D 文字を指定した行は変換せず、メッシュのまま出力します。

### 9.6 マテリアル

| 用途 | VRChat 用（既定） | Unity 標準 |
|---|---|---|
| 文字・ギミック（Lit） | VRChat/Mobile/Toon Lit | Standard |
| 文字（Unlit・発光） | 同梱の Unlit シェーダー（色・発光・透明度） | Unlit/Color 相当 |
| MatCap | VRChat/Mobile/MatCap Lit | 同梱の MatCap シェーダー |
| パーティクル | VRChat/Mobile/Particles/Additive・Alpha Blended | Particles/Standard Unlit |
| 背景ドーム | 同梱のドームシェーダー（グラデ・画像・トランジション） | 同左 |

- 時間で値を変えるもの（色・発光・透明度・切り替えの進行度）は、マテリアルのプロパティのアニメーションで行います。

## 10. モバイル最適化（独立モジュール `mesh_optimizer`）

本体と結合しない独立パッケージです。本体の Unity 出力から呼ぶほか、単体の Extension として、任意のテキスト・メッシュに使えます。

### 10.1 文字メッシュの整理（リトポロジー）

[Blender3.0/テキストのポリゴンを綺麗にする方法（signyamo.blog）](https://signyamo.blog/blender_text_retopology/) の手作業の手順を参考に、自動化します。

1. テキストの曲線の解像度（`resolution_u`）を下げる（既定 12 → 4。設定可能）。
2. メッシュに変換し、近接頂点を結合する。
3. 平面上の面をすべて溶解し、内部の辺を取り除く（限定的溶解）。
4. 穴のある字形（「口」「あ」など）を壊さないように面を張り直す。
5. 必要に応じて四角形化し、残りを三角形化する（Unity は三角形で扱うため、きれいな三角形分割を優先する）。
6. 3D 文字の場合は、整理した面から押し出しで厚みを付ける（側面の分割を最小にする）。

- 角度・しきい値は記事に値が無いため、本アドオンで既定値を決め、文字の種類（かな・漢字・英数字）で試験して調整します。

### 10.2 その他の最適化

| 対象 | 内容 |
|---|---|
| ポリゴン削減 | Decimate（Planar → Collapse）。目標のポリゴン数・比率を指定する |
| メッシュの結合 | 同時に動かない物体（静的な背景物・ギミックの部品）を結合する。文字は文字ごとに動くので結合しない（代わりにメッシュを共有する） |
| 行メッシュへの切り替え | 文字ごとのオブジェクトは描画の呼び出し（ドローコール）が多く、行が空間に溜まる「蓄積モード」では Quest で重くなる。登場の動きが終わって静止した行は、行全体を結合した1つのメッシュに切り替える（文字ごとのオブジェクトは非表示にする） |
| マテリアルの結合 | 色違いだけのマテリアルを、頂点カラーかパレットテクスチャで 1 つにまとめる |
| テクスチャ | パーティクルのテクスチャをアトラスにまとめ、解像度の上限を設ける |
| シェーダー | Lit / Unlit / Emission / MatCap だけを使う（モバイル用の簡易版） |
| パーティクル | 最大数・発生数の上限を下げる（比率で指定） |

### 10.3 目安（Quest 向け）

モバイル最適化 ON のときの既定の上限です。ワールドの規模に合わせて変えられます。

| 項目 | 既定の上限 |
|---|---|
| 1 文字あたりの三角形数 | 2D：300 / 3D：1,000 |
| 同時に表示される三角形数（演出全体） | 100,000 |
| 同時に存在するパーティクル数 | 3,000 |
| マテリアル数（演出全体） | 16 |

| 項目 | 内容 |
