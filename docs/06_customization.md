# 06. 差し替えとカスタマイズの手順

| 項目 | 内容 |
|---|---|
| 対象 | このアドオンで作ったステージの、文字の大きさ・ステージの物体（3D オブジェクト）・パーティクル・背景を、自分の好みや素材に差し替えたい人 |
| 関連文書 | [02_specification.md](02_specification.md)（仕様）、[03_detailed_design.md](03_detailed_design.md)（設計） |

---

## 1. 差し替えの 3 つの方法

| 方法 | できること | 向いている場合 |
|---|---|---|
| **A. アドオンの画面** | フォント、3D 文字、自分の 3D 物体（アセットライブラリ）、パノラマ画像の背景、パーティクル・背景の選択、量や強さ | まずはこれ。出力し直しても消えない |
| **B. アドオンのコード** | 文字・物体・パーティクルの大きさ、パーティクルと背景のプリセットの中身、新しいプリセットの追加 | 全部の曲に効く変更。Python の編集と、アドオンの入れ直しが要る |
| **C. Unity で出力の後に手を加える** | 物体のメッシュの差し替え、パーティクルの発生範囲・寿命・大きさ・画像、背景を自分の空や 3D の世界に置き換える | その曲だけの仕上げ。**出力し直すと消える** |

迷ったら、A → B → C の順に検討してください。

## 2. はじめに知っておくこと（共通の注意）

### 2.1 Unity での変更は、出力し直すと消える

- 同じ曲（同じ出力フォルダ名）をもう一度出力すると、`Assets/LyricLive/Songs/<曲名>/Generated/` を消して作り直します。Prefab・Timeline・クリップ・マテリアル・メッシュはすべて新しくなり、Unity で加えた変更は残りません（仕様書 §9.2）。
- Unity で手を加えるのは、Blender 側の作業が終わり、**最後に出力した後**にしてください。
- 後で出力し直す可能性があるなら、Unity で行った変更をメモしておき、出力のたびにやり直してください。
- 出力フォルダ名（「Unity 出力」パネル）を変えて出力すると、別の曲として別のフォルダに作られます。手を加えた版を残したまま試せます。

### 2.2 Timeline が上書きする値は、Unity で変えても戻る

生成した Prefab は、Timeline のクリップで次の値を毎フレーム書き込みます。Inspector で変えても、再生すると元に戻ります。

| 対象 | Timeline が書き込む値 |
|---|---|
| 文字（行の親・1 文字ずつ） | 表示・非表示、位置、回転、大きさ、マテリアルの色（`_Color`）、切り抜きの値 |
| ステージの物体 | 表示・非表示、位置、回転、大きさ、マテリアルの色 |
| パーティクル | 表示・非表示、発生の量（Emission の Rate over Time）、レンダラーのマテリアルの色 |
| 背景のドーム・遠景 | 表示・非表示、ドームのシェーダーの値（色・切り替えの進行度など）、遠景の色 |
| 分類のルート（Text・Particles・Background・Gimmicks） | 大きさ（1 に固定） |

次のものは Timeline が書き込まないので、Unity で変えられます。

- メッシュ（MeshFilter）、マテリアルのシェーダーとテクスチャ
- パーティクルの、上の表以外のモジュール（Start Size・Start Lifetime・Shape・Texture Sheet Animation など）
- コンポーネントの有効・無効（MeshRenderer のチェックなど）
- 子として足したオブジェクト（§4.3 で使う）

### 2.3 大きさは「目から見た角度」で決めている

- 文字と物体の大きさは、観客の目（高さ 1.5 m）から見た**角度**で決めています。遠くに置く行ほど、実際の大きさは大きくなります（仕様書 §7.1）。
- Prefab のルート（出力フォルダ名と同じ名前の、いちばん上のオブジェクト）を拡大すると、全体が観客点を中心に大きくなるだけで、観客から見た大きさは変わりません。ルートの大きさは、ワールドの床や観客の位置に合わせるときだけ変えてください。

### 2.4 権利と Quest

- 自分の物体・画像・フォントの権利（再配布・改変・ワールドへの組み込み）は、ご自身で確認してください。
- モバイル最適化（Quest 向け）は、アドオンが作ったものにだけ効きます。Unity で差し替えたメッシュ・テクスチャ・パーティクルの重さは、ご自身で Quest の上限（仕様書 §10）に収めてください。

## 3. 文字

### 3.1 アドオンの画面で

| 変えたいもの | 場所 |
|---|---|
| 書体 | 「準備」→「フォント」で、見出し・明朝・本文・等幅の 4 つを指定 |
| 立体の文字 | 行の詳細の「3D 文字」と「厚み」「ベベル」。全部の行をまとめるときは、行の一覧の上の「すべての行を 3D 文字に」 |
| 大きく見せたい語 | 歌詞に `*語*`（強調。約 1.6 倍の大きさになりやすい） |
| 長い行を大きく | 歌詞に `/` を入れて行を分ける（カット）。1 回に出る文字数が減るので、文字が大きくなる（§3.2 の幅の上限のため） |

### 3.2 アドオンのコードで（文字の大きさ）

文字の大きさは、`lyric_live_builder/core/model.py` の「text size」の定数で決まります。画面からは変えられません。

```
1 文字の大きさ（m）＝ 2 × 距離 × tan(視角 ÷ 2)
視角 ＝ TEXT_ANGLE[距離の層] × TEXT_SCALE（強調の行は さらに × EMPH_FACTOR）
```

| 定数 | 既定 | 意味 |
|---|---|---|
| `TEXT_ANGLE` | `{"near": 21.0, "mid": 21.0, "far": 21.0}` | 距離の層ごとの 1 文字の視角（度） |
| `TEXT_SCALE` | `1.0` | 全部の文字の倍率（1.5 で 1.5 倍） |
| `EMPH_FACTOR` | `5.5 / 3.5` | 強調の行の倍率 |
| `MAX_LINE_ANGLE` | `70.0` | 正面の行の最大の幅（度）。超える行は文字が縮む |
| `KEPT_LINE_ANGLE` | `38.0` | セクションの終わりまで横に残す行の最大の幅（度） |
| `SIZE_KEEP` | `0.7` | 文字が縮んでよい割合の下限。これより縮む行は、おまかせで分けたり、別のレイアウトを選んだりする |

**大きさのそろえ方（自動）**

- 「カット」が「おまかせ」の行は、正面の幅（`MAX_LINE_ANGLE`）に入りきらなければ、歌う時刻に合わせて自動で分けます。21° では、分けた 1 つは約 5 文字です。
- おまかせのレイアウトは、その行を設定の大きさの `SIZE_KEEP`（70 %）以上で置けるものだけから選びます。
- そのため、**大きさを変えても、分け方とレイアウトの選び方が自動で合います。** 大きくすると、分ける数が増え、選べるレイアウトが減ります（21° で 68 種のうち 48 種）。小さくすると逆です。
- 手で「カット」を決めた行と、「セクションの終わりまで残る」を手で選んだ行は、大きさのためには分けません。長ければ文字が縮みます。

#### 例：文字を 1.5 倍・2 倍にする

`TEXT_SCALE` の 1 か所だけを変えます。**ほかの定数とテストは、変えなくて通ります**（倍率 0.5・1.5・2・3 で単体テストが通ることを確かめています）。

```python
TEXT_SCALE = 1.5      # 1 文字 31.5°。分けた 1 つは約 3 文字
TEXT_SCALE = 2.0      # 1 文字 42°。分けた 1 つは約 2 文字
```

変えた後は §7 の手順を行います（単体テスト → zip → 入れ直し → プレビューと Unity への出力の作り直し）。行の詳細のサムネイルは、形を見せるために大きさの設定によらず 1 文字 12° で作っているので、作り直さなくてかまいません。

| 倍率 | 1 文字の視角 | 分けた 1 つの文字数（正面） | 大きさを保てるレイアウト | 注意 |
|---|---|---|---|---|
| 0.5 | 10.5° | 約 10 文字 | 68 種のうち 67 種 | — |
| 1.0（既定） | 21° | 約 5 文字 | 48 種 | — |
| 1.33 | 28° | 約 4 文字 | 31 種 | 日本語の長い行はカットが多くなる（一度この大きさにして、下げた） |
| 1.5 | 31.5° | 約 3 文字 | 22 種 | 似た見た目が続きやすい |
| 2.0 | 42° | 約 2 文字 | 13 種 | 長い行は細かく分かれ、短いカットが続く |
| 3.0 | 63° | 1 文字 | 7 種 | 1 文字ずつ順に出る |
| 3.33 まで | 70° | 1 文字 | 7 種 | 上限。これを超えると 1 文字でも正面の幅（70°）に入らず、テスト（`test_front_size_is_the_visual_angle`）が落ちる |

**それでもテストが落ちたとき**

| 落ちたテスト | 意味 | 直し方 |
|---|---|---|
| `test_front_size_is_the_visual_angle`、`test_long_lines_are_cut_to_keep_the_text_size` | 1 文字が正面の幅より大きい | `TEXT_SCALE` × `TEXT_ANGLE` を 70° 以下にする。もっと大きくするなら、`MAX_LINE_ANGLE` も上げる（下の注意） |
| `test_no_overlap_and_eye_distance` | 文字が別の行や目に近づきすぎる | 大きくしすぎなら倍率を下げる。大きさを変えると乱数の組み合わせが変わり、登場の「伸びて登場」が横に残る行と重なる組み合わせで落ちることがある（大きさとは別の、前からある問題。14° で起きた） |
| `test_thumbnails` | サムネイルが無い部品がある | 部品を足したとき。サムネイルを作り直す |

**注意**

- 長い行を 1 行のまま大きく見せたいときは、`MAX_LINE_ANGLE` を上げます。ただし 70° より上げると、正面の行が、横に残す行の席と重なります。席は `core/planner.py` の `KEEP_SLOTS`（左右 62° と 105°）です。上げるときは席の方位も外へ動かしてください。
- `KEPT_LINE_ANGLE` を上げると、隣り合う席の行どうしが重なります（62° の席と 105° の席の間は約 5° の隙間です）。セクションの終わりまで残る行は、横の席へ移るときにこの幅まで縮みます（正面で歌われている間は大きいまま）。
- `SIZE_KEEP` を下げる（例 0.5）と、使えるレイアウトが増えて分ける数が減りますが、行ごとの大きさの差が開きます。上げると逆です。
- ステージの物体は、行の幅の外に置かれるので、自動で合います。

### 3.3 Unity で

- 文字の大きさ・位置・色は Timeline が書き込むので、Unity では変えられません（§2.2）。
- 「TextMesh Pro に変換」を ON にすると、平らな文字は TextMesh Pro になります。フォントアセットは `<曲名>/FontAssets/` にできます。大きさは変わりません。

## 4. ステージの物体（3D オブジェクト）

### 4.1 アドオンの画面で（自分の物体を使う）

歌詞の語で出る物体を、自分のモデルに差し替えられます。内蔵の基本形より優先されます（仕様書 §8.3.1）。

1. 物体を .blend に入れ、Blender のアセットとして登録します（オブジェクトを右クリック →「アセットとしてマーク」）。
2. アセットブラウザで、出したい語を**タグ**に付けます（例：`cat`、`猫`）。ひらがな・カタカナ・漢字・英語の表記ゆれは、同義語の辞書で同じタグになります。
3. その .blend を置いたフォルダを、Blender のプリファレンス →「ファイルパス」→「アセットライブラリ」に登録します。
4. このアドオンのプリファレンスで「アセットライブラリ」を選び、「ライブラリを更新」を押します。
5. 辞書に無い言い方を足すときは、「追加のキーワード」に `cat=mike,tama; fox=kitsune` のように書きます。

**取り込むときの正規化**

- 高さ 1、原点は底面の中心にそろえ、その後、アドオンが観客から見た大きさに合わせます。元の大きさは関係しません。
- 正面は Blender の -Y とみなします。
- 色は、マテリアルのベースカラーとそのテクスチャを、頂点の色に写します。テクスチャそのものは使いません。
- モバイル最適化が ON のときは、三角形の数を減らします。

**どの行に出すか**は、行の詳細の「ステージの物体」「出し方」で指定できます。

### 4.2 アドオンのコードで（物体の大きさ・位置）

`lyric_live_builder/core/parts/gimmicks.py` の定数です。

| 定数 | 既定 | 意味 |
|---|---|---|
| `ANGLE` | `20.0` | 標準の物体の視角（度）。4 m 先で約 1.4 m |
| `RADIUS` | `4.0` | 物体を置く、観客からの距離（m） |
| `AIR` | `2.3` | 浮かぶ物体の高さの基準（m） |
| `SIDE` | `(38.0, 58.0)` | 行の横に置くときの、行からの角度の範囲（度）。文字に重ならないため |
| `BARS`・`BAR_RADIUS`・`BAR_WIDTH`・`BAR_HEIGHT` | `24`・`4.2`・`0.22`・`1.2` | 音のスペクトラムバーの本数・半径・幅・高さ |

`ANGLE` を上げすぎると、物体が行の文字に重なります。変えた後は §7 の手順を行ってください。

### 4.3 Unity で

- **メッシュだけ差し替える**：物体の MeshFilter に、自分のメッシュを入れます。動き（出し方）は Timeline の位置・大きさのままです。高さ 1・原点が底面の中心のメッシュなら、元の物体と同じ大きさになります。
- **大きさや向きも変えたい**：物体のオブジェクト（`Gimmicks` の下）の**子**として自分のモデルを置き、子の位置・回転・大きさで合わせます。子は Timeline が書き込まないので、変えた値が残ります。元の MeshRenderer は、チェックを外して非表示にします。
- 物体のマテリアルの色（`_Color`）は Timeline が書き込みます。自分のマテリアルに替える場合、色のプロパティの名前が `_Color` だと、色が上書きされます。

このアドオンのテストでは、§4.3・§5.3・§6.3 の Unity の手作業までは確かめていません。Unity の標準の機能での手順です。

## 5. パーティクル

### 5.1 アドオンの画面で

| 変えたいもの | 場所 |
|---|---|
| セクションのパーティクル | セクションの「パーティクル 1」「パーティクル 2」（1 つめは既定でおまかせ、2 つめは既定で指定なし） |
| 行で足すパーティクル | 行の詳細の「この行で足すパーティクル」 |
| 量 | 「演出」→「パーティクル」の強さ |
| 色 | おまかせの「スタイル」、「演出」の「独自のアクセント」 |
| おまかせで使わせない | 「演出」→「おまかせで使う部品」で、種類ごとにオン・オフ |

自分の画像をパーティクルにする機能は、まだありません（仕様書 §8.1 の予定）。今は §5.2 か §5.3 で行います。

### 5.2 アドオンのコードで

- プリセットは `lyric_live_builder/core/parts/particles.py` の `PRESETS` です。主な項目は次のとおりです。

| 項目 | 意味 |
|---|---|
| `shape` | 粒の形（2D の画像の形、または 3D の形） |
| `emitter`・`radius`・`height` | 発生する範囲（観客を囲む球・空・床・輪など）と、その大きさ（m） |
| `rate`・`max` | 1 秒あたりの量・同時に出る最大数 |
| `life`・`speed`・`size` | 寿命（秒）・速さ（m/秒）・大きさ（m）。（最小, 最大）で指定 |
| `colors` | スタイルの配色の役割（`accent`・`ghostA` など） |
| `blend` | 合成（`add` 加算／`alpha` 半透明） |

- 粒の 2D の形は、`lyric_live_builder/core/atlas.py` がプログラムで描きます（外部の画像は使っていない）。形を足すときは、ここに描き方を足します。
- おまかせは、雰囲気の好み（プリセットの `tags` と `lyric_live_builder/core/moods.py`）で選びます。
- **プリセットを足した・名前を変えた場合**：画面に出る名前の訳（`lyric_live_builder/i18n/ja_JP.py`）と、サムネイルの作り直しが要ります。サムネイルを作り直さないと、単体テストが落ちます。
- 変えた後は §7 の手順を行ってください。

### 5.3 Unity で

`Particles` の下の各 ParticleSystem で、次のものは変えられます（§2.2）。

- Main の Start Size・Start Lifetime・Start Speed、Shape（発生の範囲）、Noise など
- 自分の画像を使う：自分のテクスチャのマテリアルを作ってレンダラーに入れ、**Texture Sheet Animation のチェックを外します**。生成されたパーティクルの画像は、全部の形を 1 枚に並べたアトラスで、Texture Sheet Animation でその中の 1 マスを選んでいるためです。

次のものは Timeline が書き込むので、変えても戻ります。

- 発生の量（Emission の Rate over Time）
- レンダラーのマテリアルの色（`_Color`。出始めと消えるときの透明度もこれで動かしている）

## 6. 背景

### 6.1 アドオンの画面で

| 変えたいもの | 場所 |
|---|---|
| セクションの背景 | セクションの「背景」「トランジション」 |
| 行の途中から背景を変える | 行の詳細の「この行から背景を変える」 |
| 自分の画像を背景に | 「演出」→「パノラマ画像」に、360° の正距円筒の画像を指定し、背景で「パノラマ画像」を選ぶ |
| スタイルの色の背景 | 背景の「スタイルの色」 |

### 6.2 アドオンのコードで

- 背景のプリセット（空の色・模様・遠景の月や山並み）は `lyric_live_builder/core/parts/backgrounds.py` の `PRESETS`、切り替えは `TRANSITIONS` です。
- 背景は、指定が無ければスタイルの配色の色です（`lyric_live_builder/core/styles.py`）。空や模様の背景は、セクション・行で指定したときに使います。
- プリセットを足した場合は、§5.2 と同じく、訳とサムネイルの作り直しが要ります。

### 6.3 Unity で（自分の空や 3D の世界に置き換える）

- 背景は、観客を囲むドーム（`Background` の下の `Dome`）と遠景（`Far_…`）です。色や切り替えはシェーダーの値で、Timeline が書き込みます（§2.2）。
- 自分の Skybox や 3D の世界を見せたいときは、`Dome` と `Far_…` の MeshRenderer のチェックを外します。コンポーネントの有効・無効は Timeline が書き込まないので、外したままになります。
- そうすると、背景の切り替え（トランジション）と、ドームを使う視線の誘導の光は見えなくなります。

## 7. コードを変えた後の手順

1. **単体テスト**：Blender に同梱の Python（numpy がある）で、`tests/core` を実行します。WSL からは `sh tests/run_core.sh` です。値を変えすぎて文字が重なる場合などは、ここで落ちます。
2. **サムネイルの作り直し**（部品・プリセット・スタイルを変えたとき。文字の大きさだけなら要りません）：

   ```
   blender --background --factory-startup --python tools/make_part_thumbnails.py
   ```

   全部で約 8 分です。種類を絞るときは、環境変数 `LLB_THUMB_KINDS` に `layout,enter,hold,exit,particle,background,style` のうち作るものを入れます。WSL から Windows の Blender を動かす場合は、`WSLENV=LLB_THUMB_KINDS` も付けます。
3. **アドオンの zip を作る**：

   ```
   blender --command extension build --source-dir lyric_live_builder --output-dir dist
   ```

4. **入れ直す**：Blender で前の版を削除してから、「編集」→「プリファレンス」→「機能拡張の取得」→ 右上の ∨ →「ディスクからインストール」で zip を入れます。
5. **作り直す**：「生成」でプレビューを作り直し、Unity にも出力し直します。前に作ったプレビューと出力は、古い値のままです。

## 8. まとめ（どこで変えるか）
